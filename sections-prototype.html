Architecture

The machine behind the doodle

System overview

Four planes

Four planes: an always-on serving plane at ~$0, a CI/CD plane on GitHub Actions, an ephemeral Kubernetes plane that exists ~30 minutes a month, and a monitoring plane that closes the loop back into training.

A visitor’s drawing becomes a prediction, a log line, and — if they grade it — labeled training data. Every merge retrains, gates, and redeploys the model without a human. Every week the logs are scored for drift.

Plane 1 · always on

Serving

An always-on serving plane at ~$0. AWS Lambda wakes from zero, runs FastAPI with an ONNX model, and sends the guess back to the canvas.

  • Sendslogs, every prediction → Monitoring
  • Receivesa new model ships ← CI/CD

The wire · From Serving to Monitoring

Logs, every prediction

Every prediction Lambda serves is written to S3 as a log line. Every Monday the drift report reads that week’s logs and compares them with the training data.

Plane 2 · weekly

Evidence & drift

Every claim on the site is backed by a published artifact. The evidence hub renders from the MLflow registry. The weekly drift report scores real predictions against a reference distribution; feedback becomes a proxy-accuracy signal; a drift breach opens a GitHub issue.

The site styles all of it — including this very page — from JSON contracts, never from the platform’s own HTML.

  • Receiveslogs, every prediction ← Serving
  • Sendsdrift breach → retrain → CI/CD

The wire · From Monitoring to CI/CD

Drift breach → retrain

When drift crosses its threshold, the report opens a GitHub issue. A retrain folds the labeled drawings into the training split, and the gate decides whether the result ships.

Plane 3 · on every merge

The quality gate

Ship and re-crown are decoupled. Every training run produces a challenger; the gate compares it to the reigning champion on held-out test accuracy, with two rules — an absolute floor (0.85) and no regression beyond a small epsilon. Pass, and the challenger ships.

The champion alias only moves on a strict improvement, so “champion” always means the best-ever bar. A crippled 0.50 model is blocked in CI, deploy steps skip, and the live model is untouched.

  • Receivesdrift breach → retrain ← Monitoring
  • Sendsa new model ships → Serving
  • Sendsthe same image → Ephemeral K8s

The wire · From CI/CD to Ephemeral K8s

The same image

The image that serves on Lambda is the one Helm deploys to EKS, by digest — so the monthly load test measures the real thing, not a copy.

Plane 4 · ~30 minutes a month

Ephemeral Kubernetes

The same serving image that runs on Lambda also runs on Kubernetes — but only for ~30 minutes a month. A workflow does apply → exercise → destroy: Terraform brings up EKS and a VPC, Helm deploys the API by image digest, Prometheus scrapes it, k6 drives load, and everything is torn down.

A monthly failsafe sweeps any survivor tagged tier=ephemeral, so a botched teardown can’t quietly bill. No always-on cluster cost, anywhere.

  • Receivesthe same image ← CI/CD

The wire · From CI/CD back to Serving

A new model ships

A challenger that clears the gate is built into an image and deployed to Lambda. This is the wire that closes the loop: canvas → CI → deploy → drift → feedback → retrain.

Every claim is published

What stays running when nothing is happening: two storage buckets, one container registry, one function. Everything else is summoned on demand and torn down.
